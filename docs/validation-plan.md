# Validation Plan

## Primary question

Will a user value an independent verification layer immediately before a vulnerable transaction?

## Experimental sequence

### Phase 1 — Problem

Interview or observe users immediately before relevant transactions.

Record:

- uncertainty;
- information searched;
- checks performed;
- time spent;
- perceived consequences of failure.

### Phase 2 — Concierge verification

Before building a complete automated system, perform a limited number of verification workflows with human/AI assistance.

Record:

- evidence found;
- evidence unavailable;
- verification time;
- useful risk signals;
- decision impact.

### Phase 3 — Prototype

Provide a structured report from a URL or transaction input.

Measure:

- completion rate;
- time to report;
- evidence coverage;
- risk-signal usefulness;
- decision impact;
- stated willingness to pay.

### Phase 4 — Payment test

Test real payment intent only after the verification workflow demonstrates user value.

## Core metrics

| Metric | Definition |
|---|---|
| Verification completion | % of submitted transactions producing a usable report |
| Evidence coverage | proportion of relevant checks with usable evidence |
| Decision impact | % of users changing, delaying or confirming a decision because of the report |
| Time saved | reported or measured time avoided |
| WTP | willingness to pay for the service |
| Conversion | users completing payment |
| Repeat | users returning for another transaction |
| Referral | users referring another potential user |

## Key metric

**Decision Impact** should be treated as a primary product-learning metric.

A high report-generation rate without meaningful decision impact does not establish product value.
