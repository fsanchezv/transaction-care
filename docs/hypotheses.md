# Hypotheses

## H1 — Vulnerability

Users experience meaningful uncertainty immediately before selected property and seasonal-rental transactions.

## H2 — Evidence value

Users perceive independently organized evidence as more useful than simply receiving a generic search result.

## H3 — Decision impact

Verification can change, delay, or confirm a transaction decision.

## H4 — Willingness to pay

A subset of users will pay for verification when the transaction is sufficiently consequential and the service is delivered close to the payment/commitment moment.

## H5 — Reusable core

A meaningful portion of the verification workflow can be shared between TC-01A and TC-01B.

## H6 — Context accumulation

Repeated operation can accumulate structured transaction/evidence context that improves workflow performance and creates product defensibility.

## Falsification

The project should be reconsidered if testing shows that:

- users do not perceive meaningful uncertainty;
- evidence rarely changes decisions;
- verification cannot be performed reliably;
- willingness to pay is consistently absent;
- the cost of verification exceeds plausible revenue;
- vertical-specific requirements prevent meaningful core reuse.

These are validation criteria, not assumptions of success.
